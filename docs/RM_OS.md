# Executive Operating System Dashboard Brief — Sanitized v3

## 1. Purpose

Build one modular **Executive Operating System** that brings together professional work, owned ventures, consulting/advisory work, nonprofit/community commitments, relationships, real estate, personal life administration, vehicles, health/fitness, travel, finances, goals, learning, and public digital presence.

This should **not** be a collection of disconnected dashboards.

The system should function as a trusted command center that answers:

- What deserves attention now?
- What do I need to decide?
- What do I owe other people?
- What are other people supposed to deliver to me?
- What opportunities are moving or stalled?
- Who do I need to stay close to?
- What can be delegated?
- What is at risk?
- What is coming due?
- What should I ignore for now?
- Where does the supporting information live?

Use **fictional, generalized, or synthetic data during development**. Do not use confidential or personally identifying information.

---

# 2. Product Principles

## 2.1 One system, modular views

Build one connected operating system with independent modules feeding a unified home screen.

Modules should not duplicate data. They should reference shared objects such as contacts, projects, tasks, events, documents, opportunities, commitments, and goals.

## 2.2 Action over storage

This should not become a passive database.

The system should continuously surface:
- What needs action
- What is overdue
- What is waiting on someone else
- What is blocked
- What is approaching a deadline
- What is high value but inactive
- What should be delegated
- What can be archived or ignored

## 2.3 Reduce cognitive load

The system should make it easy to capture information without immediately organizing it.

There should always be a simple **Inbox / Add Something** function.

The user should be able to enter a rough thought such as:

- Call contact
- Renew registration
- Follow up on proposal
- Book appointment
- Idea for venture
- Check insurance
- Make introduction
- Donate clothing

The system can then classify or suggest where it belongs.

## 2.4 Separate active work from possibilities

Every project, venture, idea, opportunity, and commitment should support clear status such as:

- Active
- Waiting
- Delegated
- Incubating
- Someday / Maybe
- On Hold
- Complete
- Archived

This prevents interesting ideas from becoming false priorities.

# 42. Developer UX Guidance

The dashboard should feel:
- Calm
- Simple
- Executive
- Fast
- Mobile friendly
- Easy to scan
- Easy to capture into
- Difficult to clutter

Avoid:
- Too many widgets on the home screen
- Excessive charts
- Too many statuses
- Requiring multiple fields for quick capture
- Forcing every idea into a project
- Requiring the user to organize before capturing
- Duplicating the same information across modules

Prefer progressive disclosure:
- Show what matters first
- Allow deeper details when needed

# 44. North Star

The goal is **not** to put everything on one screen or track every possible detail.

The goal is to create one trusted system that tells the owner:

- What deserves attention
- What needs a decision
- What is next
- What is overdue
- What is blocked
- What has been delegated
- What is waiting on someone else
- What opportunities are moving
- Who needs attention
- What important deadline is approaching
- What can be ignored
- Where the supporting information lives

The system should reduce mental clutter, protect important commitments, improve follow-through, and help the user spend more time on high-value decisions, relationships, opportunities, health, and meaningful work.
